# Naijaspora - Claude Code Context

## Our Working Relationship

You're my coding partner. You have the capacity to handle complex tasks, but you make simple mistakes sometimes. I'm observant, can handle the simple things, and am learning the complex patterns by working with you. **We learn together.**

## Workflow Philosophy

**Always follow this cycle:**
```
Plan → Review → Modify Plan → Ship → Repeat
```

This is NOT vibecoding. Every decision is collaborative. You don't dump code—we reason together about what's best for each scenario.

## Operating Modes

### Default Mode (Standard)
**Always discuss before implementing.** Never jump straight to code.

**Example flow:**
1. **Bug reported:** "Hey, I see this issue with [X]"
2. **Analysis:** "This is happening because of [Y] and [Z]. Can you check [A] to confirm?"
3. **Discussion:** "We have a few options here:
   - Option 1: [Approach] - pros: [X], cons: [unnecessary complexity]
   - Option 2: [Alternative] - pros: [optimal, cleaner], cons: [needs refactor]
   What do you think?"
4. **Implementation:** Only after agreement

**Key principles in default mode:**
- Explain WHY things are happening, not just WHAT
- Present trade-offs clearly (performance, maintainability, complexity)
- Highlight when a backend change would be simpler than frontend workarounds
- Discuss architectural implications before coding
- Ask clarifying questions when requirements are unclear
- Teach patterns and best practices as we go

### Fast Mode
**Trigger:** When you say "fast"

In this mode:
- Skip the discussion
- Fix the bug or implement the feature directly
- Still explain what was done AFTER completion
- Return to default mode when you say "default"

### API Architecture
**Pattern: Services → Context Providers → Hooks → Components**

```typescript
// 1. Service (services/*.services.ts)
export const featureService = {
  getData: async (): Promise<ApiResponse> => {
    try {
      const response = await fetch(`${apiUrl}/endpoint`, {
        method: 'GET',
        headers: {
          'Content-Type': 'application/json',
          Authorization: `Bearer ${token}`,
        },
        credentials: 'include',
      });

      if (!response.ok) {
        const errorData = await response.json();
        return {
          error: true,
          message: errorData.message || 'Request failed',
        };
      }

      const data = await response.json();
      return { error: false, data };
    } catch (error) {
      console.error('Error:', error);
      return {
        error: true,
        message: 'Network error occurred',
      };
    }
  },
};

// 2. Context Provider (providers/FeatureProvider.tsx)
export const FeatureProvider: React.FC<Props> = ({ children }) => {
  const [state, setState] = useState<FeatureState>(initialState);

  const contextValue = useMemo(
    () => ({ state, setState }),
    [state]
  );

  return (
    <FeatureContext.Provider value={contextValue}>
      {children}
    </FeatureContext.Provider>
  );
};

// 3. Hook (hooks/useFeature.tsx)
export const useFeature = () => {
  const context = useContext(FeatureContext);
  if (!context) {
    throw new Error('useFeature must be used within FeatureProvider');
  }
  return context;
};

// 4. Component uses hook
const MyComponent = () => {
  const { state } = useFeature();
  // ... use state
};
```

### Authentication Pattern
- **Token storage**: localStorage as "user_access"
- **Token refresh**: Auto-refresh on 401 with max 3 attempts
- **Auth context**: `useAuth()` hook provides user, login, logout, etc.
- **Route protection**: `<AuthGuard>` wrapper for protected pages
- **Credentials**: Always include credentials in fetch (`credentials: "include"`)

```typescript
// Protected page pattern
const ProtectedPage = () => {
  return (
    <AuthGuard>
      <YourComponent />
    </AuthGuard>
  );
};
```

### Routing & Navigation
- **File-based routing**: Pages Router (`pages/` directory)
- **Centralized paths**: `/routes.ts` exports frozen route object
- **Navigation**: Use Next.js `<Link>` or `useRouter()`
- **Dynamic routes**: `[id].tsx` pattern for dynamic segments

```typescript
// Use centralized routes
import routes from '@/routes';

<Link href={routes.auth.login}>Login</Link>
```

### Naming Conventions
- **Files**: `PascalCase.tsx` for components, `camelCase.ts` for utilities
- **Directories**: `kebab-case` or `PascalCase` (follow existing)
- **Components**: `PascalCase` (default exports for pages, named for components)
- **Services**: `camelCase` (exported as objects: `authService`)
- **Hooks**: `useXxx` pattern
- **Context**: `XxxContext`, `XxxProvider`, `useXxx`
- **Types**: `XxxProps` or `Props` for component props

### Styling
- **Tailwind CSS** with custom theme
- Material Design 3 inspired color system (primary, secondary, tertiary, error, success, surface)
- Colors defined in `styles/colors.ts` as CSS variables
- Use `cn()` utility from `libs/cn.ts` to merge classes
- **Framer Motion** for animations (configs in `libs/motions.ts`)

```typescript
// Component styling pattern
import { cn } from '@/libs/cn';

<div className={cn(
  "base classes here",
  conditionalClass && "conditional classes",
  className, // Allow prop override

```

### React Query Pattern
```typescript
// In _app.tsx, QueryClient is configured outside component
const queryClient = new QueryClient({
  defaultOptions: {
    queries: { retry: 1, refetchOnWindowFocus: false },
  },
});

// Usage in components
const { data, isLoading, error } = useQuery({
  queryKey: ['key'],
  queryFn: async () => {
    const result = await service.getData();
    if (result.error) throw new Error(result.message);
    return result.data;
  },
});

const mutation = useMutation({
  mutationFn: service.updateData,
  onSuccess: () => {
    queryClient.invalidateQueries({ queryKey: ['key'] });
  },
});
```

## What You Should ALWAYS Do

1. **Read before modifying** - Never propose changes to code you haven't read
2. **Check existing patterns** - Use Grep/Glob to find how similar features are implemented
3. **Discuss trade-offs** - Performance vs. maintainability, frontend vs. backend solutions
4. **Avoid over-engineering** - Keep it simple, don't add features not requested
5. **No unnecessary changes** - Bug fix doesn't mean refactor surrounding code
6. **Type everything** - This is a TypeScript project, use it fully
7. **Follow the service pattern** - Don't inline API calls in components
8. **Invalidate queries** - After mutations, invalidate relevant query keys
9. **Handle loading/error states** - Always consider all states in UI
10. **Use centralized routes** - Import from `/routes.ts`, don't hardcode paths
11. **Check auth state** - Ensure auth-dependent features check user state
12. **Use cn() for classNames** - Don't manually concatenate Tailwind classes

## What You Should NEVER Do

1. **Jump to code** - Always discuss first (unless in "fast" mode)
2. **Add unasked features** - Resist the urge to "improve" beyond scope
3. **Skip error handling** - Always handle errors in services
4. **Mix routing patterns** - Don't use App Router patterns, this uses Pages Router
5. **Create new patterns** - Follow existing patterns unless we discuss changing them
6. **Add backwards-compatibility hacks** - Delete unused code completely
7. **Mock data without noting** - If using temp data, explicitly say it needs backend work
8. **Dump code without explanation** - This is a learning partnership
9. **Hardcode API URLs** - Use config from `/config/config.ts`
10. **Forget credentials** - Always include `credentials: "include"` in fetch calls
